# Life Context — 产品定位与边界

更新：2026-10-11。状态：方向共识与设计草案；功能、架构和商业模式尚未冻结。

## 产品定位

Life Context 是用户拥有、可持续修正的个人上下文库，为不同的、经过授权且技术兼容的 agent 提供有依据的个性化背景。

产品介绍：从用户选择的聊天记录和自述中整理个人上下文，由用户确认和修正，让不同 AI 在与其实际情况相关的背景下提供帮助。

“agent 外部工具”描述技术接入方式。“个人上下文库”表达用户价值。开发者层面可描述为“面向 agent 的个人数据管理与上下文服务”。不承诺完全了解用户，也不承诺所有客户端自动读取或正确理解内容。

## 当前方向共识

- 核心目标：经过多次 agent 更新后，上下文仍然准确、可纠正，用户维护成本足够低。
- 核心来源包括用户选择的聊天记录、用户自述、决定及实际结果。原始来源与提取出的认识需要相互连接。
- 产品围绕个人上下文组织。项目接续是候选首场景，帮助获得高频使用机会；它不限定长期产品边界。
- 问卷和画像分析属于后续探索，不进入当前最小范围。
- 研究联系按广义 AI/Data Infrastructure 理解。工程联系、产品差异化和研究新颖性分别验证。

这些共识不等同于完整 PRD 审批。具体存储、客户端、采集方式和审批策略仍见决策日志。

## 核心对象

| 对象 | 保存内容 | 作用 |
|---|---|---|
| 来源记录 | 作者/说话者、时间、原文或摘录、消息或文档位置、内容版本 | 检查用户表达了什么、当时处于什么情境 |
| 上下文条目 | 目标、约束、偏好、承诺、决定及其来源、有效范围、状态 | 提供精简、可修正的当前背景 |
| 核心文件 | 针对任务从已确认状态生成的背景，带版本、来源索引和权限范围 | 供人和 agent 阅读的任务上下文视图 |
| 决定与结果 | 当时预期、实际选择、后续结果及证据 | 支持复盘与长期自我认识 |

三个层次代表不同用途，避免把所有内容保存三份。核心文件可以采用 Markdown；它与底层记录如何一致更新，仍需明确契约。文件可读性不决定权威存储必须采用文件。

## 可靠性的具体含义

1. 提取忠实：正确表达原文，保留情境、否定和条件。
2. 当前有效：过期、撤回、被替代或待确认的认识不被无提示地当成当前事实。
3. 依据充分：本人陈述、第三方表达、行为记录与 agent 推断明确区分。
4. 容易纠正：用户修正后，后续读取使用新状态；旧版本可按权限追溯。
5. 成本可接受：采集、确认、纠错的总成本低于获得的使用收益。

聊天记录证明某人曾表达某句话，无法自动证明其内容客观正确。用户确认表示认可进入上下文，仍需保留认识的性质和适用范围。签名、哈希或读取凭据也不证明语义真实或模型理解正确。

## 候选最小范围

个人卡与一个活跃项目；任务上下文读取；集中确认变更；少量决定与结果记录；完整导出恢复。macOS、两个明确支持的客户端是试验范围建议，尚未形成发布承诺。

从用户选择的小样本来源开始。不自动摄入全部聊天、邮件或附件；没有人格打分、自动生活建议、团队协作、移动端、自动消息发送或多设备同步。

暂不制作任务看板和日程管理。全文或语义检索可以辅助查证，首版价值需要从上下文维护与实际任务收益中验证。

## 所有权、增长与迁移

用户控制访问、导出和删除。大型原件初期优先引用，保存少量必要摘录与来源标识；明确区分系统托管内容与外部链接。来源丢失必须可见，内容指纹不能恢复原件。

任务分析默认临时生成，只保存选中的决定与结果。索引和可重新生成的核心文件允许重建。任何缓存清理策略都需要先确定唯一证据是否仍可恢复，不能静默删除唯一副本。

跨客户端连接与整库迁移分别验收。开放导出包应覆盖正式记录、历史、证据关系、状态和权限范围，并列明附件覆盖情况；普通分享导入不能凭文件自称 owner 来源。受信恢复与外部导入的信任规则需单独设计。
